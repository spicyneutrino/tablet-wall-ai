### Lifecycle and recovery

1. **Join and identity.** The operator shares the tablet listener's `/client/` URL or QR, not the laptop's loopback URL. `localStorage['tablet-wall-device-id']` retains a UUID4. Generation tries guarded `crypto.randomUUID()`, then insecure-context-capable `getRandomValues()`, then explicitly warned non-cryptographic `Math.random()`. Storage failure yields a usable session identity but no guarantee across reloads. `tablet-wall-device-number` retains a requested display number, which is distinct from identity. Changing scheme, host, or port changes storage origin. Rebind is an operator action, not inferred identity recovery. Evidence is [frontend/client/client.js:216](../../../frontend/client/client.js:216), [frontend/client/client.js:291](../../../frontend/client/client.js:291), [frontend/client/client.js:317](../../../frontend/client/client.js:317), [main.py:966](../../../main.py:966), [docs/tablet-wall-readiness/HARDWARE-ACCEPTANCE.md:44](../../../docs/tablet-wall-readiness/HARDWARE-ACCEPTANCE.md:44).
2. **Register before every connection attempt.** `POST /devices/register` reports `device_id`, `width/height = innerWidth/innerHeight`, `device_type` from Android/iOS/other detection, optional screen dimensions, DPR, platform family, previous number, and wake-lock state. Viewport dimensions describe usable CSS area, not physical millimetres. Registration has a 10-second timeout and precedes socket creation. Server re-registration preserves assigned colour, label, number and current connection facts. Restored registrations begin offline after server restart. Evidence is [frontend/client/client.js:468](../../../frontend/client/client.js:468), [main.py:966](../../../main.py:966), [tabletwall/state.py:235](../../../tabletwall/state.py:235).
3. **Connect and replay.** Opens same-origin `ws:` or `wss:` `/ws/device?device_id=...&protocol=3&caps=...&w=...&h=...&dpr=...&orientation=...&mode=...&visual_scale=...`. Caps are `calibration,image,physical,render_ack,identify,image_contain`; `video` is added only when `canPlayType(H.264 MP4)` is nonempty. Welcome establishes connection ownership, number, heartbeat interval and resets ordering. Server immediately sends clock bootstrap and current state, then any assigned colour. Evidence is [frontend/client/client.js:56](../../../frontend/client/client.js:56), [frontend/client/client.js:2632](../../../frontend/client/client.js:2632), [frontend/client/client.js:4666](../../../frontend/client/client.js:4666), [main.py:3456](../../../main.py:3456).
4. **Heartbeat and resume.** Heartbeat normally runs every 5 seconds, refreshes render evidence, retries wake lock when due, and sends `{type:'heartbeat',wake_lock}`. Server presence expires after 15 seconds, with a 2-second sweeper. Client also retires a socket after 15 seconds without incoming activity. Clock exchange supplies recurring traffic even for a still scene. `online`, `pageshow` and visible return probe registration, redraw, send viewport and clock sample; `pagehide` reports hidden and retires the socket. An OS-frozen page cannot execute this code until resumed. Evidence is [frontend/client/client.js:711](../../../frontend/client/client.js:711), [frontend/client/client.js:2675](../../../frontend/client/client.js:2675), [frontend/client/client.js:2850](../../../frontend/client/client.js:2850), [tabletwall/protocol.py:13](../../../tabletwall/protocol.py:13).
5. **Retry/backoff.** Connection failure does not terminate the loop. Delay starts at 500 ms, doubles, adds up to 25% positive jitter, and caps the resulting delay at 5 seconds. Welcome resets the delay. The nearby comment saying 15 seconds is stale. A 10-second registration or welcome timeout can add to this delay, so the constants do not prove a 10-second physical recovery result. Evidence is [frontend/client/client.js:76](../../../frontend/client/client.js:76), [frontend/client/client.js:4747](../../../frontend/client/client.js:4747), [frontend/client/client.js:4813](../../../frontend/client/client.js:4813).
6. **Ownership and auth.** A new socket takes the one live slot for a UUID. Close `4409` makes the losing page stop retries and require the visible Take over action; it must not cause a replacement storm. A registration `401` pauses connection work and shows `/auth/login?next=<local URL>`. A probe finding login `403/404/405` instead displays deployment guidance. A WebSocket handshake denial alone is not a reliable HTTP-status signal to browser JS. Evidence is [frontend/client/client.js:173](../../../frontend/client/client.js:173), [frontend/client/client.js:678](../../../frontend/client/client.js:678), [frontend/client/client.js:4851](../../../frontend/client/client.js:4851), [main.py:3220](../../../main.py:3220), [tabletwall/auth.py:113](../../../tabletwall/auth.py:113).
7. **Wake lock.** Secure context and API detection precede `navigator.wakeLock.request('screen')`. States are `held`, `released`, `unsupported`, `insecure`, `denied`. Hidden pages release; visible return reacquires; lost or denied locks retry at most every 30 seconds from the heartbeat. This does not control Guided Access, power management or OS sleep. Safari 15 has no API, even over HTTPS. Evidence is [frontend/client/client.js:2706](../../../frontend/client/client.js:2706), [deploy/KIOSK.md:16](../../../deploy/KIOSK.md:16) and the support matrix below.
8. **Fullscreen.** Gesture-only button uses standard or WebKit-prefixed enter/exit methods, is offered only when the root has an API, and fades after five seconds. It does not automatically enter fullscreen or survive a reload as a kiosk policy. Fullscreen events invalidate the viewport mapping. `launchMode()` returns `fullscreen`, `standalone` from display-mode media query, or `tab`. Evidence is [frontend/client/client.js:2498](../../../frontend/client/client.js:2498), [frontend/client/client.js:2595](../../../frontend/client/client.js:2595).
9. **Identify.** Opaque command, connection and generation checks reject stale delivery. Server duration is constrained to 1–10 seconds. Client also checks expiration using sampled server time when available and local monotonic plus wall-clock deadlines, so sleeping `performance.now()` cannot extend the flash. Number/label are assigned with `textContent`. It reports `shown` after an animation frame and `cleared` on expiry/clear. This temporarily obscures content and cannot count as current image display. Evidence is [frontend/client/client.js:630](../../../frontend/client/client.js:630), [main.py:2343](../../../main.py:2343), [docs/OPERATOR-PROTOCOL.md:34](../../../docs/OPERATOR-PROTOCOL.md:34).
10. **Offline operation.** All client scripts/styles/assets come from the LAN origin. No WAN is needed while the LAN service is reachable. There is no service worker or supported cold-offline page cache. Socket loss cancels old image work and video, then restores the remembered static scene descriptor while attempting recovery. A retained raster or browser HTTP cache is not a durable offline mode. The tablet does not poll `/wall` or `/api/v3/config` as a fallback; the controller has polling/reconciliation. Evidence is [frontend/client/client.js:1643](../../../frontend/client/client.js:1643), [frontend/client/client.js:4634](../../../frontend/client/client.js:4634), [frontend/client/client.js:4775](../../../frontend/client/client.js:4775), [deploy/KIOSK.md:36](../../../deploy/KIOSK.md:36).

### Geometry ownership and exact equations

Let image dimensions be `Iw,Ih`, wall bounds `W,H`, viewport/render rectangle `Vw,Vh`, and logical placement `x,y,w,h` with bezel `l,r,t,b`.

**Logical path, computed on the tablet.**

```text
visible = (vx,vy,vw,vh) = (x+l, y+t, w-l-r, h-t-b)
s_view = max(Vw/vw, Vh/vh)
ox = (vw - Vw/s_view)/2
oy = (vh - Vh/s_view)/2
s_image = cover ? max(W/Iw,H/Ih) : min(W/Iw,H/Ih)
dw = Iw*s_image; dh = Ih*s_image
dx = (W-dw)/2; dy = (H-dh)/2
```

The canvas maps wall coordinates using uniform `s_view`, translates by `-(vx+ox),-(vy+oy)`, clips the visible rectangle, paints the scene background and draws the one wall-centred image rectangle. The viewport itself clips overflow. Thus Fill/Fit is wall-wide, followed by an independent viewport cover of each logical visible rectangle. Mismatched logical viewport aspect can crop further; Fit whole image does not imply every pixel appears on every logical tablet. The server supplies layout and intrinsic image facts, not this final logical transform. Evidence is [frontend/client/client.js:876](../../../frontend/client/client.js:876), [frontend/client/client.js:2043](../../../frontend/client/client.js:2043).

**Physical path, split between server and tablet.**

```text
body width  = active_width_mm + left_bezel + right_bezel
body height = active_height_mm + top_bezel + bottom_bezel
active origin = (-body_width/2+left_bezel, -body_height/2+top_bezel)
M_panel_to_wall = T(center+nudge) * R(mount_angle) * T(active_origin)
F_normalized_source_to_wall = wall-wide cover/contain fit at bounds.x,bounds.y
G = inverse(M_panel_to_wall) * F_normalized_source_to_wall   [server]
U = T(panel_offset_mm) * Q(quarter_turn,viewport_mm_size) * S(mm_per_css)
D = S(backing_width/rect_width,backing_height/rect_height)
    * inverse(U) * G * S(1/rendition_width,1/rendition_height) [tablet]
```

The server computes `G`, panel clip, body/active geometry, and source metadata from the slot's exact immutable profile/calibration revisions. The tablet composes its CSS-to-panel calibration and actual backing ratios. Matrices are `[a,b,c,d,e,f]`, column-vector convention, rightmost first, clockwise positive in Y-down coordinates. DPR sizes the backing raster, never supplies physical millimetres. Backing width/height are rounded separately, so actual X and Y ratios can differ slightly. Evidence is [tabletwall/geometry.py:131](../../../tabletwall/geometry.py:131), [tabletwall/state.py:477](../../../tabletwall/state.py:477), [frontend/client/view.js:209](../../../frontend/client/view.js:209), [frontend/client/view.js:238](../../../frontend/client/view.js:238), [frontend/client/client.js:933](../../../frontend/client/client.js:933), PROTOCOL.md:779.

`physicalTransform()` derives a CSS clip from the full active panel dimensions. Stills multiply its matrix by actual backing ratios; video uses the same CSS matrix in an overflow-hidden layer and subtracts the clip origin. The current still client rebuilds the full active-panel clip through `canvasTransformComponents`, rather than consuming arbitrary `plan.clip` shapes. A migration must preserve this actual rectangle behavior and must not assume arbitrary clipping is supported. Evidence is [frontend/client/client.js:1956](../../../frontend/client/client.js:1956), [frontend/client/client.js:1974](../../../frontend/client/client.js:1974), [frontend/client/client.js:4064](../../../frontend/client/client.js:4064), [frontend/client/view.js:268](../../../frontend/client/view.js:268).

Viewport validity requires CSS dimensions within 1 px, DPR within 0.02, exact orientation and launch mode, matching pinned profile, plus zoom checks. Client zoom guard uses 0.001 from scale 1; server mapping uses 0.01. Resize/orientation/visual-viewport/fullscreen changes immediately clear physical plans and stop playback; socket viewport produces a new plan without changing wall revision. Width/height changes re-register after a 400 ms debounce. Built-in approximate model calibrations can adapt through `tablet_models.effective`; manual measured calibration cannot be silently rescaled. Evidence is [frontend/client/client.js:2418](../../../frontend/client/client.js:2418), [frontend/client/client.js:2606](../../../frontend/client/client.js:2606), [tabletwall/state.py:366](../../../tabletwall/state.py:366), [tabletwall/state.py:412](../../../tabletwall/state.py:412), [tabletwall/tablet_models.py:145](../../../tabletwall/tablet_models.py:145).

### Experimental still/video playback

The client has substantial video support, but the README scopes demonstrated hardware to still images. Video is capability-gated H.264 MP4 with muted inline video elements, no native loop, physical CSS matrix/clip shared with stills, prepared/armed/active slots, clock-compensated starts, buffer readiness, activation handling, drift sampling and bounded recovery. A visible Enable display button handles a withheld play gesture. Preparation is invisible until commit and must not overwrite the persisted static scene. Stop, epoch change and socket loss return to that static scene. Evidence is [frontend/client/client.js:2816](../../../frontend/client/client.js:2816), [frontend/client/client.js:3290](../../../frontend/client/client.js:3290), [frontend/client/client.js:3682](../../../frontend/client/client.js:3682), [frontend/client/client.js:4013](../../../frontend/client/client.js:4013), [frontend/client/client.js:4209](../../../frontend/client/client.js:4209), [frontend/client/client.js:4634](../../../frontend/client/client.js:4634), [README.md:14](../../../README.md:14).

Clock bootstrap starts eight samples at 100 ms spacing, then samples every 5 seconds. Client estimates offset using four timestamps. Server accepts readiness only with fresh clock evidence and uncertainty at most 25 ms. Ready renews every 500 ms with a 2-second lease. Video drift correction has 50 ms deadband, up to ±2% rate correction through 250 ms, then a local seek at most once per 5 seconds. `requestVideoFrameCallback` is detected; a time/polling fallback exists. Recovery handles metadata, seek, buffer, play permission, a 2.5-second frame-stall detector and bounded local/group attempts. These contracts must remain even if the first React controller presents playback only behind the existing experimental opt-in. Evidence is [frontend/client/client.js:2850](../../../frontend/client/client.js:2850), [frontend/client/client.js:3220](../../../frontend/client/client.js:3220), [frontend/client/client.js:4350](../../../frontend/client/client.js:4350), [frontend/client/view.js:310](../../../frontend/client/view.js:310), PROTOCOL.md:888, PROTOCOL.md:1066.

## 2. Backend interfaces

### Admission and concurrency conventions

The following tables enumerate the actual route decorators in `main.py` and `tabletwall/routes`, plus middleware/static/FastAPI routes. `C` means the current operator workspace; `T` means tablet; `L` means compatibility controller or legacy API; `X` means experimental playback/storage. `TS` marks proposed React API ownership, not a route that should be rewritten.

All routes are subject to optional shared-secret authentication **A**. When `TABLET_WALL_AUTH_TOKEN` is unset, A is inert. When set it must be at least 32 bytes. HTTP accepts a matching bearer or signed 12-hour `tablet_wall_session` cookie. Cookie writes and cookie WebSockets require exactly one same-origin Origin. Browser sockets naturally use the cookie; the client does not put bearer tokens in the WebSocket URL. Unauthenticated HTML reads redirect to login, other requests get 401, and denied sockets fail the handshake. Authenticated HTTP responses are private/no-store. Evidence is [tabletwall/auth.py:15](../../../tabletwall/auth.py:15), [tabletwall/auth.py:113](../../../tabletwall/auth.py:113).

### WebSocket contracts

Both sockets are JSON text messages over same-origin `ws:`/`wss:`. Device socket query and ownership are described above. `/ws/controller?protocol=3` is a read/event stream; the server receives and discards incoming messages except disconnect. Controller mutations are HTTP, not socket commands. Absent protocol negotiates 1; supported majors are 1, 2 and 3. A physical wall refuses a non-v3 controller with 4426. Migration invariants, proposed regression gates:

1. Preserve whole-wall Fit/Fill and physical units. Never substitute per-tile `object-fit:cover`, DPR-to-mm estimates, or per-device image normalization. Run the existing matrix oracle/client tests for arbitrary angle, asymmetric bezel, nudge, nonzero bounds, clipped viewport and fractional DPR.
2. Preserve every layout kind, fixed/tablet bounds, custom grids such as 1×3, 2×3 and 3×2, explicit order and allowed trailing holes. Keep separate expectations for v3 pack, legacy pack and equal-cell tile. Their rounding and size semantics differ.
3. Preserve immutable pins, provenance and uncertainty. Updating a profile/calibration cannot re-pin a displayed or saved arrangement. Approximate model scale is not physical seam acceptance.
4. Preserve preview/apply separation, opaque ETags, connection/viewport guards, local dirty draft protection and uncertain-mutation recovery. A live roster update must not silently reshape a reviewed grid.
5. Preserve reservations, participation, session exclusions, offline labels/numbers, rebind consequences and saved-layout repair choices. Include an absent roster entry with a retained slot in tests.
6. Preserve ordering at all layers: new generation resets revision comparisons; same revision with newer render_seq can repaint; six-field render token fences async decode and report; playback adds epoch/session/version/occurrence/preparation ownership.

### Recommended build and CSS policy

**Recommendation:** keep `/client/` as its independent no-build classic-script app for the controller migration. Do not move the renderer, reconnect loop or CSS into the React controller bundle. Serve its current local assets and maintain per-file cache tokens plus no-cache revalidation. The first client change should be a small separately validated compatibility patch for waiting backdrop/focus handling, not a framework conversion.

If later code sharing or TypeScript justifies a client build, use a separate entry and configuration emitting a small self-contained classic IIFE, with syntax ceiling **ES2019** and explicit **Safari14 + Chromium87** targets. ES2019 forces optional-chain/nullish/class-field lowering even though some target browsers implement them. Require no top-level await, no runtime CDN and no default modern-bundler target. API availability is separate from transpilation; keep wake/fullscreen/UUID/frame-callback/decoder guards. Do not add large blanket polyfills for capabilities whose absence already has a working local state. Source maps can support lab debugging without changing render geometry. This is a proposed output policy, not a newly measured build artifact.

**Plain CSS is the preferred client choice.** Tailwind **v3** is conditionally feasible if built on the host, scoped to a separate client stylesheet, audited against the explicit browser floor, and restricted to supported utilities. Its `@layer` authoring directive can be compiled away; do not confuse that with shipping native cascade layers. Autoprefixer alone does not implement unsupported `:has`, viewport units, container queries or `aspect-ratio`. The v3 docs describe modern stable-browser testing and advise avoiding unsupported utilities, not blanket support for every old tablet. [Tailwind v3 browser support](https://v3.tailwindcss.com/docs/browser-support).

**Tailwind v4 is unsafe for this client target.** Official v4 minimums are Safari16.4, Chrome111 and Firefox128. Core modern dependencies cannot be made Safari15-safe merely by lowering the JS target. Keep v4/shadcn-generated controller CSS out of the tablet document; a modern controller-only target can be chosen independently. [Tailwind compatibility](https://tailwindcss.com/docs/compatibility).

### Design-skill rules applied to this recommendation

- **Impeccable, Operate and brief-first restraint.** Preserve Direction B's main wall, single inspector, image strip and stepped Measure flow. The tablet itself remains a quiet display with actionable recovery.
- **frontend-design, existing content and clear state language.** Preserve explicit “Needs calibration”, image failure, retry, authentication and waiting semantics. Reuse existing token intent without importing an operator reset that changes fullscreen display geometry.
- **frontend-ui-engineering, fetching separate from presentation and simple state ownership.** Put server authority and socket reconciliation behind one typed session. Make the measurement UI consume it rather than own a competing copy.
- **vercel-react-best-practices, `client-event-listeners`, `bundle-conditional`, `rerender-derived-state`.** One subscription/socket owner, optional playback code loaded only for its operator task, and derived display summaries instead of duplicated status stores.
- **web-design-guidelines, native buttons/labels, visible focus and async state announcements.** Keep the tablet's native controls and live recovery text. Early Safari15 needs a visible focus fallback. The ruler already traps Tab and focuses its heading, but has no Escape handler and does not make the underlying document inert. If changed, test and complete the dialog interaction rather than claiming `role=dialog` alone establishes modality. Evidence is [frontend/client/ruler.js:15](../../../frontend/client/ruler.js:15), [frontend/client/ruler.js:78](../../../frontend/client/ruler.js:78); [current guideline rules](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md).
- **accessibility-inclusive-design, progressive enhancement and explicit hidden state.** Preserve live regions, textual waiting/error cues and touch targets. Do not disable zoom as a mapping workaround. A zoomed physical display should fence the mapping and keep readable recovery guidance. Reduced-motion behavior for fading HUD/controls needs validation when those controls change; current client CSS has no reduced-motion query.

### Modern Web Guidance

I searched screen wake lock and dynamic viewport units, and retrieved `responsive-design` and `css`. The wake-lock search produced no relevant wake-lock guide, so API claims use MDN instead. `responsive-design` recommends “Use dynamic viewport units”, and `css` recommends “Use cascade layers”. The declared Safari15/WebView87 policy overrides those default modern-browser assumptions. I retained baseline fallback sizing and recommend ordinary unlayered CSS/root state attributes. No `:has`, container-query or dynamic-unit dependency should be introduced solely because it is Baseline-wide for current browsers. No implementation changes were made.
