## Shared visual and component rules

Keep the existing locally loaded Schibsted Grotesk. Body and controls use 16px with 1.5 line height; metadata uses 14px. Task titles use 28px desktop and 26px phone, weight 600. Section titles use 20px desktop and 18px phone. Use the current 6px control radius and 1px dividers. Prefer open rows and meaningful media frames over repeated section cards.

Keep `--bg #f8f3e9`, `--surface #fffcf6`, `--text #1e1a15`, `--muted #5e574f`, `--control #74695c`, `--accent #9d4616`, `--success #246344`, `--attention #795500`, and `--error #a12a24`. Retain the charcoal stage. A complete side-by-side composition comparison with unchanged tokens supports retention; no new font or palette has earned its implementation cost here.

Use an 8px spacing base, 12px internal action gaps, 16px component gaps, 24px task-section gaps, and 32px desktop column gaps. Content can grow. Numbers in this brief describe the observed fixture and starting constraints, not fixed-height text containers. Break to one column when the content cannot sustain the gallery plus a useful selected-object column; the prototype uses 700px. Check the intermediate tablet width separately.

Keep five patterns with explicit purposes. A task header identifies location. A thumbnail choice selects an image without showing it. A roster row identifies a registration and exposes Identify. A wall figure depicts truthful geometry with an external caption. A commit review places the named scope, warning, command and result together. Contextual error/review blocks are additional states of those patterns, not a parallel dashboard.

Filled dark buttons are commits. Preview and ordinary editing use outlined buttons. Disclosures and quiet utilities have less weight. Recovery is shown only when actionable. Destructive commands use error text and their existing review. Active navigation has an underline and weight, selected art has a check and border, and preview figures have an explicit label plus dashed body boundaries. Color supplements text and shape.

The shared header contains connection count, applied arrangement, and current output evidence, with a pending-intent indicator when needed. Let it wrap. Do not create KPI cards, repeat setup advice above every task, or retain a historical "waiting" sentence after current reports have arrived. Extended revision, session, ETag, mapping and asset details remain labelled disclosures. Actionable approximation and stale-base warnings stay beside the relevant review.

## Geometry and truth stay authoritative

Use the existing geometry and wall-wide Fit/Fill transform. Fit the viewBox to actual bounds and available drawing space, independently of content fit. Do not stretch a tablet, silently rotate its mount, fill a bezel with art, or change Fit/Fill to improve the screenshot.

The fixture has 177.4 × 240.4mm bodies, 147 × 210mm active panels and 15.2mm model bezels. Its 2×2 body bounds are 354.8 × 480.8mm; 1×4 bounds are 709.6 × 240.4mm. The portrait 2×2 preview therefore remains tall. These are approximate model dimensions with pinned profile/calibration revision 1, not new measurements. The prototype clips one wall-wide image to the four active rectangles and leaves the actual bezel areas visible.

Images emphasizes the audience artwork without central identity chips. Tablets emphasizes identity and evidence outside active art. Arrange exposes boundaries, true gaps, dimensions, overlap, membership and preview state. Keep IDs and statuses accessible outside the SVG. Production diagnostic numbers must remain at least 14 CSS pixels or move to external labelled controls when the physical bezel cannot fit them. Prototype SVG numbers scale with geometry and are not an approved label implementation.

Current reports always refer to applied output, even while a local preview is displayed. An offline reservation occupies its existing position. Label it "Offline · position reserved" and hatch it; do not imply that the server knows what its physical screen currently shows. Current matching software reports are evidence of the client render path, not optical proof of lit hardware.

## State and focus contracts

Derive presentation from existing applied state, active keyed output intent, per-identity field drafts, operation outcome, and current-tablet predicates. Do not create a second authority to drive the new layout. The prototype's local state is a throwaway fit check, not a replacement for these domain owners.

| State | Visible treatment and allowed next action |
| --- | --- |
| Live | Show applied arrangement and matching current image-report count. Do not equate connected with showing. Hide irrelevant recovery controls. |
| Local image preview | Label "Image preview · not shown". Keep selected art, fit and Show adjacent. View live retains that exact draft and offers View preview. |
| Local arrangement preview | Label "Arrangement preview · not applied". Show geometry change, exact subjects, warning and Apply. Content remains the applied selection, with any crop consequence explained. |
| Accepted, awaiting reports | Record server acceptance, then show N matching current reports. Clear the waiting condition only when current predicates resolve it. Never copy prior output evidence onto new geometry/content. |
| Failed image | Name affected tablets and the failed stage. Keep server acceptance separate. Offer targeted retry where valid; clear failure only after matching evidence. |
| Offline or stale | Preserve reservations and identify missing evidence. Stale connection/configuration cannot appear healthy. Keep stale-base review near its disabled commit. |
| Conflict | Preserve local fields and preview. Offer the existing compare/review path with exact changed values. Rebuild requires explicit intent against reviewed current authority. |
| Uncertain write | State that the outcome is unknown. Disable duplicate commit while reconciling. Resolve from authoritative state under the existing operation/subject fences. A timeout is neither success nor safe automatic retry. |
| Empty | No tablets leads Tablets with joining. No arrangement leads Arrange with connection/setup guidance. Empty Images leads with admitted Add image; an empty library does not erase an operating wall's evidence. Empty Saved explains the two record types. |
| Loading or unavailable | Keep the task heading and truthful loading/unavailable text. Inventory loading is not an empty library. Readiness failure is not a healthy checklist. Expose labelled retry without fabricating prior data freshness. |
