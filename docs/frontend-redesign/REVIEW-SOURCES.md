## Agreement

One wall-centred workspace, contextual tasks, guided first arrangement, plain
language, image upload and choice together, clear live/preview status, responsive
local action controls and preserved deep state/lifecycle/security behavior.
Reference typography/tokens should support a control surface, not a landing page.

## Differences the synthesis must resolve

- Opus proposes one pending Make live command for arrangement plus image. Sol
  warns that separate backend commands cannot safely imply atomic combined Apply.
- Opus proposes Saved walls bundling arrangement/image/fit. Sol preserves existing
  saved-arrangement meaning and asks for a deliberate schema/transaction decision.
- Opus proposes bulk model confirmation and replacement suggestions. Both must
  retain explicit hardware intent, historical pins and partial-failure visibility.
- Opus proposes moving focus to the panel on selection. Sol distinguishes task
  opening from roster selection and protects keyboard focus during live updates.
- Compatibility retirement needs an explicit capability migration, including
  logical custom placement, image replacement, saved scenes and diagnostic colour.
- Both identify loopback-only operator upload opt-in as the safe path to fulfill
  in-app image addition on the supported hotspot profile. It needs admission,
  launcher and generated-ingress verification, not a cosmetic upload button.
