# Decisions

- Safety. Before any app launch, backed up SQLite with its online backup API and copied media to `/tmp/tablet-wall-ai-backup-20261028-010950`. Tests and browser runs use disposable data paths.
- Workflow. Use independent worktrees for authentication, frontend extraction, robustness, and tooling/deployment. Integrate only reviewed commits with passing checks.
- Scope. Complete at least six rounds with phone, tablet, and desktop browser checks in each. A final review is supplementary and cannot replace these rounds.
- Data. Restart persistence restores safe device metadata as offline; online state must come from live sockets.
- Delivery. Use feature branches and logical PRs; no deploy or merge is authorized.
- Extraction. Moved asset HTTP handlers to `tabletwall/routes/assets.py` unchanged. The module depends on existing asset/media services and has no mutable app context or circular main import. This reduces main.py while preserving patchable service dependencies.
- Extraction. Moved read-only registry and registration-help routes into `tabletwall/routes/devices.py`. Mutation and WebSocket ownership remain together in main.py pending larger extractions. Full tests bracket each extraction.
- Type boundaries. Keep strict optional checks enabled. Narrow parsed origins, image asset IDs, display revisions, and viewport strings at their existing validation boundaries; give playback preparation a distinct variable from clock probe evidence.
- Extraction. Moved operator diagnostics and its read-only storage helpers into `tabletwall/routes/diagnostics.py`. Existing admission policy and payload are unchanged; the route directly uses the existing media/persistence services and live registry.
- Verification failure. Diagnostics extraction removed shutil even though upload admission still uses it. Full tests caught 15 wrong 500 responses. Restored the import and reran the full suite before committing the extraction.
- Authentication. Protect all HTTP and WebSocket routes with opt-in shared-secret middleware. Browsers get signed expiring HttpOnly cookies; cookie writes and sockets require same-origin Origin. Configured authentication also forces private,no-store responses to prevent shared-cache disclosure.
- Persistence. Reused the versioned schema_meta table instead of inventing a migration for safe roster metadata. Delete/rebind share a synchronous task-local SQLite transaction with wall changes. Live presence is always rebuilt from sockets. Contact checkpoints run every 60 seconds and at shutdown.
- Cache. Retained capped current-file reads and SHA-256 on every lookup. Cached only successful decode facts, bounded to 256 entries, so preserving stat metadata cannot hide changed bytes. Five alternating request rounds and untimed profiles show decode work removed while reads and response contents remain correct.
- Tools. Added Ruff E4/E7/E9/F and mypy with strict optional checks over production code. Coverage includes subprocesses and an 80 percent combined floor. Existing weak host-network scripts remain pending real-host validation; hub failure/reconnect tests raise local error-path coverage.
- Features. Existing undo/redo, bulk colour, diagnostics export, and one-flow database/media backup already satisfy the ranked feature needs. A visible health overview and explicit stale roster feedback improve the highest-ranked remaining operational gap.
- Frontend extraction. Preserved classic script ordering and IIFE ownership. Logical geometry, snapshots, stage/history, and inventory/uploads use explicit factories or runtime getters. Physical playback and stage editing share the existing state object. Each extraction has its own green full-test commit.
- Frontend correction. Independent review found ApiError was an undeclared identifier in the new playback module. Passed the original constructor explicitly and tested one 412 retry, repeated-conflict limits, and friendly409 errors.
- Health. Reused the roster and existing profile/calibration facts for an above-stage summary. Failed refresh retains last-known data with a timestamp and retry control; it no longer presents that data as freshly online.
- Agent limit. Frontend and review agents hit a provider usage limit. Main thread inspected their worktrees, verified terminal handles, completed the saved health patch and error regression tests, and continued integration without restarting duplicate workers.
- Final benchmark check. Route extraction broke the benchmark route-discovery assumption. The integrated benchmark now binds the extracted asset handler directly and clears inherited deployment settings. Five repeated alternating request rounds passed again with identical output/work counts.
- Exit audit. Eleven rendered audit rounds completed. Rounds10 and11 found no new issues above polish after all fixes. Baseline and final reports, failed-probe explanations, per-extraction full-test evidence, and final gate outputs support BACKLOG closure.
